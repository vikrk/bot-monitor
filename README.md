# RVKOMI Server Control

Установочный репозиторий строится на действующем `rvkomi-telegram-control`. В `control/` перенесены исходники этого бота, его планировщиков, домашнего мониторинга и systemd-служб. ИИ охватывает SPB, NL, DNS, WWW, SPACE, FIN, LATVIA и домашний роутер.

GoTelegram/MTProxy сюда не входят и не изменяются. Токен отдельного Server Manager не используется для контрольного бота. Старый самостоятельный Server Manager сохранён как дополнительный вариант установки через пункт 2.

## Установка основы контрольного бота

На Ubuntu 22.04/24.04:

```bash
curl -fsSL -o hosts.tar.gz https://github.com/vikrk/hosts/archive/refs/heads/master.tar.gz
tar -xzf hosts.tar.gz
cd hosts-master
sudo bash install.sh
```

В меню выберите `1`. Скрипт положит исходники в `/usr/local/lib/rvkomi-watchdog`, системные настройки — в `/etc/rvkomi-watchdog`, состояние и историю — в `/var/lib/rvkomi-watchdog`. Конфигурации, SSH-ключи и токены в репозитории не хранятся.

Настройте Telegram-бота командой:

```bash
sudo rvkomi-control-setup
```

Введите токен существующего контрольного бота (ввод скрыт) и ID его личного чата. Не вводите токен Server Manager: он не предназначен для этой службы. Один Telegram-токен нельзя одновременно опрашивать с двух серверов. При переносе сначала остановите polling на старом сервере, затем запускайте новый.

Перед запуском добавьте защищённые файлы конфигурации и SSH-ключи существующих node-агентов в `/etc/rvkomi-watchdog`. Установщик намеренно не переносит их с TELEGRAM и не публикует. После подготовки:

```bash
sudo systemctl enable --now rvkomi-telegram-control.service
```

Дополнительные таймеры и router receiver устанавливайте после переноса соответствующих настроек из текущей конфигурации. Для домашнего роутера требуется также настроить HTTPS reverse proxy к `rvkomi-router-receiver`; установщик не меняет существующие правила Nginx.

Для установки отдельного менеджера выберите пункт `2` или запустите `sudo bash install-server-manager.sh`. Не требуется для ИИ-интеграции существующего контрольного бота.

## ИИ-диагностика в текущем боте

В меню доступна кнопка «ИИ-анализ всех узлов». Она запускает свежие полные проверки семи согласованных серверов, читает состояние домашнего роутера, историю результатов и системный журнал службы управления. Узел TELEGRAM исключён из ИИ-обхода, чтобы не задевать MTProxy/GoTelegram. Перед отправкой данных маскируются распознаваемые токены и ключи. ИИ только анализирует и предлагает следующие действия. Ответ модели не исполняется; доступные действия остаются за текущими функциями бота и их существующими подтверждениями.

Текущие node-агенты не предоставляют отдельное SSH-действие для чтения их systemd-журналов. Поэтому сейчас используются полные отчёты проверок, история проверок и локальные журналы управляющих служб; удалённые журналы служб узлов потребуют отдельного чтения через ограниченный RPC в node-агентах.

Для OpenAI API:

1. Войдите в [OpenAI API Platform](https://platform.openai.com/api-keys) и создайте отдельный API-ключ. Полный ключ показывается только при создании; если потеряли его, создайте новый.
2. На сервере выполните `sudo rvkomi-ai-setup`.
3. Укажите API URL (`https://api.openai.com/v1`), точное имя доступной модели и вставьте ключ в скрытый запрос.

Ключ сохраняется только в `/etc/rvkomi-watchdog/ai.json` с правами `0600`. Он не входит в GitHub и не передаётся через Telegram. API-ключ OpenAI — отдельный от Telegram-токена; наличие подписки ChatGPT не задаёт автоматически настройки API.

Notion можно использовать для памятки по установке и списка моделей/параметров. Сам API-ключ в Notion не сохраняйте — вводите его только в скрытый запрос на сервере. Создание и управление OpenAI API-ключами описаны в [официальной справке OpenAI](https://help.openai.com/en/articles/4936850-where-do-i-find-my-openai-api-key).

## Данные и ограничения

- ИИ-запрос выполняется только после нажатия кнопки в личном чате.
- В запрос передаются результаты проверок, состояние роутера, ограниченная история и локальный журнал контрольных служб выбранному API-провайдеру.
- Результаты проверок и журналы могут содержать данные, которые не распознаются маской. Проверьте, что выбранный API-провайдер подходит для этих данных.
- ИИ не запускает перезапуски, shell-команды, reboot или изменение конфигурации.
- `GoTelegram` и `telemt` не входят в состав служб для диагностики или действий.
- Server Manager использует собственный Telegram-токен и не участвует в этой интеграции.
