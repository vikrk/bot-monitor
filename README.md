# RVKOMI Server Manager

Отдельный управляющий проект для серверов и SSH-роутеров. Исходники GoInstaller и GoTelegram не входят в проект и не изменяются.

## Меню

1. Состав установки и системные изменения.
2. Подключение другого сервера — имя, IP, SSH-пользователь, одноразовый пароль для установки ключа.
3. Установка Telegram-бота — подключение токена и привязка администратора.
4. Настройка интервала мониторинга.
5. Подключение роутера по SSH.
6. Список узлов и их состояние.
7. Разовая проверка узла.
8. Исправление после подтверждения в Telegram.
9. Журнал действий.
10. Резервная копия и восстановление конфигурации.
11. Управление доступом администратора.
12. Диагностика управляющего сервера.
13. Отключение сервера или роутера и отзыв ключа.
14. Выход.
15. Задать имя основного сервера и зарегистрировать его без SSH-параметров.
16. Добавить DNS-маршруты и проверить их доставку до журнала AdGuard.
17. Настроить ИИ-диагностику.

## Состав

- Python 3, systemd-служба, локальная SQLite база узлов и действий.
- Исходящие SSH-соединения с отдельным ключом менеджера.
- Telegram long polling, один привязанный Chat ID, управление узлами, DNS-проверки и inline-подтверждение действий.
- Проверки доступности SSH и базовой загрузки; журнал проверок.
- Разовая DNS-проверка для DoH-origin, DoH-CDN, DoT, DNS-relay-DoH/DoT и AdGuard DoH/DoT. Для каждой пробы создаётся уникальное имя; успех засчитывается только если оно найдено в query log AdGuard на выбранном узле.
- ИИ-диагностика по кнопке узла: последние результаты всех типов проверок, записанных менеджером (до 50 записей), последние 50 действий и журналы до 80 строк каждой службы из фиксированного списка за последние два часа. Для локального узла службе даётся read-only доступ к системному журналу через группу `systemd-journal`; на удалённом узле SSH-пользователь должен иметь доступ к journal. Токены и распространённые форматы ключей/паролей маскируются перед отправкой.
- Для ИИ используется OpenAI-compatible Chat Completions API по HTTPS. По умолчанию предлагается Groq (`https://api.groq.com/openai/v1`, модель `openai/gpt-oss-120b`); провайдера можно заменить. Результаты проверок и журналы узла передаются выбранному оператором API-провайдеру; ввод API-ключа скрыт, он хранится в `bot.env` с правами `0640`. Запросы происходят только по нажатию «ИИ-диагностика».
- ИИ только анализирует и предлагает действия. Исправления ограничены перезапуском `ssh`, `nginx`, `docker`, `gokaskad`, `rvkomi-server-manager`, `AdGuardHome`, `kaskad-egress`, `kaskad-bot` и `kaskad-monitor`; любое действие требует отдельного подтверждения в Telegram. GoTelegram/MTProxy исключён и из журналов, и из списка перезапуска. Произвольные команды и исполнение команд, предложенных моделью, не поддерживаются.
- Бэкап и восстановление базы без SSH-ключа и токена бота.

## Установка

На Ubuntu 22.04/24.04:

```bash
sudo bash install.sh
sudo fleetctl
```

При установке задайте только название основного сервера. Установщик сам поставит зависимости и службу, создаст локальную запись основного сервера в инвентаре и включит мониторинг этого узла. IP, SSH-пользователь, пароль и отдельный SSH-ключ для основного сервера не нужны. Для смены названия после установки используйте пункт 15.

Если Telegram-бот ещё не настроен, после установки выберите пункт 3, чтобы привязать токен и личный Chat ID. После привязки служба запускается автоматически. Для основного сервера проверки выполняются локально; перезапуск разрешённых служб требует подтверждения в Telegram и использует отдельный список разрешённых команд sudo.

Для подключения другого сервера или SSH-роутера укажите имя, адрес и SSH-пользователя. При первом подключении оператор сверяет fingerprint SSH-хоста и подтверждает его. Пароль читается без отображения и используется только для установки публичного ключа, затем не сохраняется. Приватный ключ создаётся на управляющем сервере. Публичный ключ целевого узла ограничивается внешним IP управляющего сервера; если определить IP не удалось, установка ключа отменяется.

### ИИ-диагностика

На управляющем сервере запусти `sudo fleetctl` → пункт 17. Укажи HTTPS base URL OpenAI-compatible API, модель и API-ключ (ввод скрыт). В Telegram нажми «ИИ-диагностика всех узлов»: бот последовательно обойдёт каждый включённый сервер и роутер и выдаст отдельный отчёт по каждому; можно также запустить анализ из карточки одного узла. Для каждого узла будут собраны недавние результаты проверок, записи аудита и журналы служб из фиксированного списка, секреты замаскированы перед отправкой. Проверка не запускает исправления. ИИ видит результаты проверок, которые пишет Server Manager, и диагностические журналы `kaskad-monitor`; тесты, которые ещё не перенесены в Server Manager и не записываются в доступные журналы, в отчёте не появятся. Для применения разрешённого действия вернись в карточку узла и отдельно подтверди перезапуск одной из разрешённых служб.

Журналы могут содержать данные, которые не распознаются автоматической маской; перед использованием выбери API-провайдера, которому доверяешь. Отключение ИИ — удалить `AI_API_KEY`, `AI_MODEL` и `AI_BASE_URL` из `/etc/rvkomi-server-manager/bot.env` и перезапустить службу.

### DNS-проверка в Telegram через журнал AdGuard

В боте открой «DNS-маршруты», выбери узел и добавь нужные маршруты. На карточке узла эта же настройка доступна кнопкой «DNS-маршруты». Для похожего узла можно скопировать набор маршрутов как шаблон; путь к журналу задаётся отдельно для каждого узла. Для DoH отправь полный HTTPS URL, например `https://dns.example.org/dns-query`; для DoT — `dns.example.org:853`. По умолчанию задаётся 1 проба для origin/CDN/DoT и 16 для DNS-relay-DoH/AdGuard DoH либо 4 для DNS-relay-DoT/AdGuard DoT; количество можно настроить от 1 до 64.

В боте выбери «Задать путь к журналу» и отправь абсолютный Linux-путь к `querylog.json` на узле AdGuard. Файл должен быть читаем учётной записью приложения (для основного сервера — пользователем службы). «Проверить сейчас» отправляет уникальные запросы и до 25 секунд ищет их в последних 8 MiB журнала. Ответ DNS и отправка пакета сами по себе успехом не считаются. Проверка не меняет настройки AdGuard и не включена в фоновый мониторинг.

### Telegram по сценарию goKaskad

1. В `fleetctl` выберите «Установка Telegram-бота» и введите токен от @BotFather.
2. Выберите автоматический Chat ID, откройте бота в Telegram и отправьте `/start`; либо задайте Chat ID вручную.
3. Проверьте тестовое сообщение; служба запускается автоматически.

Секреты хранятся в `/etc/rvkomi-server-manager/bot.env` с правами `0640` и группой службы. В Telegram доступ разрешён только привязанному личному Chat ID.

## Ограничения первой версии

Роутеры подключаются по стандартному SSH. Проверка узла использует `uptime` и `df -P`; совместимость зависит от shell и ОС устройства. Если на роутере нет POSIX shell или OpenSSH, менеджер сообщит об этом и не будет подменять команды. Мониторинг и доступные исправления задаются отдельно для каждого узла.

Пока менеджер не развернут, он не подключается к серверам и не меняет их настройки.
