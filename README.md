# RVKOMI Server Control

Установочный комплект разворачивает существующий `rvkomi-telegram-control` вместе с его проверками и планировщиками. В целевой конфигурации мониторятся SPB, NL, DNS, WWW, SPACE, FIN, LATVIA, TELEGRAM и домашний роутер. ИИ-анализ подключается к этому же контрольному боту при наличии сохранённой настройки OpenAI API.

`GoTelegram`/MTProxy и `GoInstaller` не входят в этот путь установки и не изменяются. Отдельный Server Manager оставлен только для совместимости; для полного мониторинга выбирайте пункт **1**.

## Перенос на новый управляющий сервер

Для сохранения существующего бота и подключений сначала создайте зашифрованную runtime-копию на текущем управляющем сервере:

```bash
sudo rvkomi-control-runtime export
```

Задайте длинную парольную фразу не короче 14 символов. Команда создаст `/root/rvkomi-control-<дата>.enc` с настройками контрольного Telegram-бота, AI, узлов, их SSH-ключами и pinned `known_hosts`, настройками домашнего роутера, параметрами резервного копирования и доступными данными состояния. Парольную фразу передайте отдельно от файла. В копию попадают секретные ключи, поэтому передавайте и храните её только защищённым способом.

Скопируйте `.enc` на новый Ubuntu-сервер, например через защищённое соединение:

```bash
scp root@OLD_CONTROLLER:/root/rvkomi-control-<дата>.enc /root/
```

Установите комплект на новом сервере:

```bash
curl -fsSL -o hosts.tar.gz https://github.com/vikrk/hosts/archive/refs/heads/master.tar.gz
tar -xzf hosts.tar.gz
cd hosts-master
sudo bash install.sh
```

В меню оставьте выбор `1`. Укажите путь к `.enc` и введите парольную фразу. Установщик проверит SSH/RPC-доступ `status` ко всем восьми серверам до запуска бота и мониторинговых таймеров. Если доступ не проходит из-за смены исходящего IP, он предложит добавить новый адрес к ограничениям **существующих** SSH-ключей с проверкой закреплённого fingerprint и без сохранения введённых паролей. При отказе проверки службы не запускаются.

Задайте период мониторинга (по умолчанию 2 минуты). Перед включением polling подтвердите, что бот остановлен на старом управляющем сервере: Telegram не разрешает двум экземплярам одновременно получать обновления одним токеном. После подтверждения установщик регистрирует команды и включает `rvkomi-telegram-control`, периодические проверки и ежедневные проверки сертификатов. Таймер резервного копирования включается только при наличии WebDAV-настроек и ключа восстановления.

Проверьте результат в Telegram: откройте меню текущего контрольного бота и запустите проверку узлов. Код и доступные таймеры можно проверить командами:

```bash
sudo systemctl status rvkomi-telegram-control rvkomi-extra-monitor.timer rvkomi-certificates.timer
sudo rvkomi-control-verify
```

`rvkomi-control-verify` делает только read-only `status` запросы и не перезапускает службы.

### Домашний роутер

Установщик восстанавливает конфигурацию агента и, если runtime-копия содержит TLS-сертификат, настраивает отдельный Nginx virtual host только для `/task` и `/report`. Если Nginx ещё не установлен, он устанавливается при свободном порте 443. Существующий virtual host с тем же доменом автоматически не переписывается; при конфликте router-службы остаются выключены.

Для перехода на новый управляющий сервер DNS-имя роутера (в сохранённой конфигурации сейчас `rvkomi.online`) должно указывать на новый сервер. Пока DNS ведёт на старый узел, heartbeat продолжит приходить туда. После переключения DNS проверьте HTTPS и heartbeat в боте. Не удаляйте старую конфигурацию, пока новый узел не принял heartbeat.

### Чистая первичная установка

Для переноса существующей инфраструктуры runtime-копия обязательна: ключи, fingerprints и токены намеренно не публикуются в GitHub. Без неё установщик остановится до запуска, поскольку не сможет безопасно подключиться к серверам. Для новой инфраструктуры сначала подготовьте оба списка узлов и SSH-доступ с закреплёнными fingerprints; автоматическое создание доверия к неизвестным host keys отключено.

## ИИ-диагностика

Настройка OpenAI API хранится в `ai.json` с правами `0600`; ключ API отдельный от Telegram-токена. Если файл уже был в runtime-копии, дополнительная настройка не требуется. Иначе выберите настройку в установщике или выполните:

```bash
sudo rvkomi-ai-setup
```

Укажите `https://api.openai.com/v1`, имя доступной модели и API-ключ в скрытом запросе. Создать ключ можно на [странице API keys](https://platform.openai.com/api-keys). Оплата ChatGPT не включает автоматически баланс API.

ИИ-запрос отправляется по команде владельца из Telegram. В анализ входят актуальные проверки, состояние роутера, ограниченная история и локальный журнал контрольных служб. Система маскирует распознаваемые секреты перед отправкой, однако диагностические данные могут включать адреса узлов и фрагменты сообщений. ИИ формирует предложения, но сам не исполняет shell-команды, перезапуски или reboot.

## Что запускается

- `rvkomi-telegram-control.service` — существующий контрольный Telegram-бот.
- `rvkomi-extra-monitor.timer` — периодические проверки DNS, WWW, SPACE, LATVIA, FIN и TELEGRAM.
- `rvkomi-certificates.timer` — ежедневные предупреждения о сертификатах.
- `rvkomi-backup.timer` — ежедневная зашифрованная копия, если восстановлены WebDAV и recovery key.
- `rvkomi-router-receiver.service` и `rvkomi-router-monitor.timer` — только если настроен HTTPS endpoint роутера.

Секреты и runtime-файлы не хранятся в GitHub. Отдельный Server Manager (`install-server-manager.sh`) не подключает мониторинг текущего fleet-бота и для описанного переноса не нужен.
