# Соответствие действующему боту и новая установка

Код перенесён из rvkomi-telegram-control, прочитанного на TELEGRAM
13 октября 2026 года, и адаптирован к задаваемому при установке списку узлов.
В GitHub переносятся код и установщики; токены, пароли, ключи, реальные IP,
домены и рабочие конфигурации владельца не публикуются.
Сторонние установочные комплекты не входят в состав проекта.

## Возможности

| Рабочий бот | Установочный пакет |
|---|---|
| ИИ-анализ /ai_all | Свежие проверки, журналы подключённых узлов, подробная история ошибок |
| ИИ-планы /ai_change | Планировщик и проверка структурированного предложения; подтверждение на 2 минуты |
| Точные изменения Xray | Только добавление доменов в уже существующее proxy-правило |
| DNS-перезаписи AdGuard | Явные domain:-записи на адрес relay, введённый владельцем |
| Правила и подписки AdGuard | Добавление/удаление/замена точных строк, публичные HTTPS-подписки |
| SNI | Добавление/удаление доменов и явное назначение одного backend существующей карты |
| Роутер | Диагностика SSH; с Python и UID 0 — выбранные Entware init-скрипты |
| История ошибок | schema_version=2, exit/http/error_detail, диагностика в /history и контексте ИИ |
| Мониторинг | 120 минут по умолчанию; с локальным checker можно выбрать только status |
| Журналы | journald/Xray/nginx 72h, AdGuard 6h; история бота 30 дней |

Меню использует список, заданный владельцем. Имя узла используется в меню
и ИИ-запросах. Начинайте запрос с имени и двоеточия:
«Мой DNS: добавь domain:example.org».
Модель по умолчанию повторяет рабочую настройку gpt-4.1-mini; модель и
отдельный API-ключ можно задать самостоятельно.

## При установке управляющего сервера

1. Выберите пункт 1 install.sh, задайте имя, своего бота и администратора.
2. Настройте ИИ API: ключ вводится скрыто, сохраняется только локально.
3. Выберите разрешённые перезапуски служб основного сервера.
4. При необходимости включите дополнительные возможности ИИ.
5. Задайте период мониторинга: по умолчанию 120 минут.

Без дополнительных полномочий доступны диагностика и явно выбранные
перезапуски; операции над правилами не включаются автоматически.

## Подключение узла и адрес relay/FIN

В fleetctl выберите подключение сервера, введите своё имя узла, IP/DNS,
SSH-пользователя и порт. При настройке профиля выберите пункт 8.

- Для Xray разрешите добавление доменов в существующие proxy-правила.
- Для AdGuard укажите абсолютные пути YAML и исполняемого файла.
- Для DNS-перезаписей введите **публичный IPv4 relay/FIN**. Значения по
  умолчанию нет. Адрес является параметром профиля, а не константой кода.
- Для SNI укажите существующий .conf, имя переменной backend в map без $,
  публичный IP и порт relay, домены для TLS-проверки. Сам SNI-сервис и карта
  этим пунктом не создаются. Публичный адрес берётся только из профиля.
- Для Entware укажите конкретные имена служб и пути /opt/etc/init.d/...
  На роутере нужны Python и административные права; без них остаётся
  SSH-диагностика без обещания выполнения исправлений.

Подключение устанавливает агент и обработчики ИИ через подтверждённый
административный SSH-сеанс. Пара ключей создаётся на управляющем сервере;
ключ ограничивается его IP и командой агента. ИИ использует ограниченный
JSON RPC агента. Чужие ключи или конфигурации не требуются.

Обычные URL/TLS/DNS-проверки редактируются пунктом 4. Изменение
административных полномочий удалённого узла требует пункта 14
«переподключить»: они не расширяются обычным RPC configure.
Локальный профиль контроллера редактируется от root без переподключения.

## Диагностика и применение

/ai_all ничего не меняет. /ai_change запрашивает один узел и одно действие,
показывает точный план, риски и кнопку подтверждения. /cancel отзывает
ожидающие планы. Callback принимает только владельца; кнопка одноразовая,
привязана к сообщению и действует две минуты. Исполнитель повторно проверяет
полномочия, поля и контрольную сумму конфигурации перед изменением.
Shell-команды, SSH/firewall-правки и reboot в ИИ-протокол не входят.

При изменениях сохраняются копии и выполняются предусмотренные
обработчиком проверки; при неуспехе — предусмотренный откат.
Обрыв связи не считается подтверждённым успехом; автоматического
повторного применения нет. Аудит ИИ хранится локально с правами 0600.

/dns_sni_check проверяет узлы с настроенными DNS/SNI-возможностями.
SNI-домены после подтверждённого изменения включаются в последующие
TLS-проверки. Для узла с локальным checker пункт 9 профиля позволяет
читать status; неизменившийся результат не считается новой проверкой.
Остальным узлам планировщик отправляет свежий check.

## Существующие установки и восстановление

Публикация репозитория не меняет действующие серверы. Импорт зашифрованной
runtime-копии — отдельное явное действие. В копию включаются настройки ИИ,
административный инвентарь и связанные SSH-ключи, выбранный период мониторинга.
Без импорта устанавливается свой контроллер со своим списком и настройками.

Специализированные legacy-исполнители сохраняют свои ограничения при
импорте. Новые узлы используют портативные обработчики. Для импортированного
SPB сохраняется status локального checker; в новой инфраструктуре этот
режим выбирается в профиле нужного узла.

Команды после установки:

    sudo rvkomi-control-verify
    sudo systemctl status rvkomi-telegram-control rvkomi-extra-monitor.timer
    sudo cat /var/lib/rvkomi-watchdog/diagnostic-logging-status.json

Развёртывание нового комплекта и применение ИИ-изменений на тестовом сервере
отдельно от публикации не выполнялись.
